# BITS Pilani MLOps Assignment 01

An end-to-end binary heart disease classification service using the UCI
Cleveland Heart Disease dataset, scikit-learn, MLflow, FastAPI, Docker, and
Kubernetes.

## Dataset and labels

The downloader retrieves the official UCI Cleveland archive and writes the
processed 303-row dataset to `data/heart.csv`. The CSV contains the 13 patient
features and the `target` column. Source missing-value markers are imputed with
the column median for continuous values and the mode for categorical values.
The original Cleveland target is converted to binary: `0` means no disease;
original values `1` through `4` mean disease. The checked-in data is the
processed data generated by the downloader.

## Setup and training

Use Python 3.11 for local development, matching the container image.

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m data.download_data
python -m src.eda
python -m src.train
```

Training runs five-fold stratified cross-validation for Logistic Regression
and Random Forest. Each fold fits its own imputer and scaler to prevent data
leakage. Accuracy, precision, recall, F1, and ROC-AUC means and standard
deviations are recorded in MLflow under the `heart-disease-classification`
experiment. The model with the strongest mean ROC-AUC is refit on all rows and
exported to `models/heart_disease_model.pkl`.

MLflow uses a local `mlruns/` directory by default. Set `MLFLOW_TRACKING_URI`
to use a tracking server instead.

## API

Start the API after training has generated the model artifact:

```bash
uvicorn api.main:app --host 0.0.0.0 --port 8000
```

- `GET /health` reports service and model readiness.
- `POST /predict` accepts the 13 Cleveland features and returns a binary
	`prediction` plus `confidence`, the estimated probability of disease.
- `GET /metrics` exposes Prometheus request and prediction counters.

Example request:

```bash
curl --fail http://localhost:8000/predict \
	--header 'Content-Type: application/json' \
	--data '{"age":63,"sex":1,"cp":1,"trestbps":145,"chol":233,"fbs":1,"restecg":0,"thalach":150,"exang":0,"oldpeak":2.3,"slope":3,"ca":0,"thal":6}'
```

## Docker

Build the model first, then build and run the image:

```bash
docker build -t heart-disease-api .
docker run --rm -p 8000:8000 heart-disease-api
```

The runtime image uses Python 3.11 slim and runs as the unprivileged `appuser`.
Its healthcheck calls `/health`. The model artifact must exist before building.

## Kubernetes and monitoring

Build and publish the image, then update `image` in
`k8s/deployment.yaml` to the published image reference. Apply the resources:

```bash
kubectl apply -f k8s/deployment.yaml
kubectl apply -f k8s/service.yaml
kubectl apply -f k8s/hpa.yaml
```

The service is `LoadBalancer` on port 80 and forwards to container port 8000.
The deployment starts two pods, uses rolling updates, 512Mi/500m resource
limits, and `/health` probes. The HPA scales from two to ten replicas at 70%
average CPU utilization. Configure Prometheus with `monitoring/prometheus.yml`
to scrape the service's `/metrics` endpoint; the target assumes the default
Kubernetes namespace.

GitHub Actions runs linting, dataset preparation, model training and artifact
validation, tests, and a Docker build with endpoint smoke checks on pushes and
pull requests to `main`.
